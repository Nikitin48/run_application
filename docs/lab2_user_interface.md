```
Главное меню
 ├── Карта (Map)

 │     └── [FAB] Управление забегом
```

## Контрольные вопросы

**1. CUA и классификация окон**

CUA (Common User Access) — стандарт SAA IBM, определяющий типы окон: основные (primary), вторичные (secondary), диалоговые, модальные, немодальные, окна сообщений.

В данном приложении окна классифицированы следующим образом:
- **Первичное диалоговое**: экран авторизации (LoginPage) — основная точка входа с формой ввода.
- **Основные бездиалоговые**: карта (MapPage), история забегов (HistoriesPage) — отображение данных без обязательного ввода.
- **Основное смешанное**: профиль (ProfilePage) — сочетает отображение информации и формы редактирования.
- **Вторичное**: итоги забега (RunSummaryPage) — открывается поверх основного потока навигации.
- **Вспомогательное модальное**: диалог выбора цвета территории — блокирует фоновый экран.
- **Вспомогательное немодальное (оверлей)**: панель управления забегом (FAB) — не блокирует взаимодействие с картой.

**2. Структура меню и классификация опций**

Опции классифицированы как:
- **Переход к новому уровню меню** — Карта, История, Профиль (три ветви нижней навигации).
- **Действие с модальным окном** — выбор цвета территории.
- **Переключатель** — «Следовать за мной», тестовый режим.
- **Действие** — старт забега, пауза, финиш, сохранение профиля, смена пароля.
- **Моментальное действие** — выход из аккаунта, pull-to-refresh.

Меню представлено в виде дерева, включающего 13 пунктов и 3 уровня.

**3. Диаграмма состояний диалога**

Состояния отражают то, что отображается на экране пользователя: форма ввода (авторизация), данные (карта, история, итоги), управление (забег), информация (профиль). Переходы определяются действиями пользователя: нажатие кнопок, жесты навигации, ответы сервера.

Система имеет 9 состояний и 14 переходов. Ключевая особенность — жизненный цикл забега (покой → отсчёт → бег → пауза → завершение → итоги) реализован как цепочка состояний внутри экрана карты, а не как отдельные экраны.
