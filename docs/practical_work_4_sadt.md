## Ход работы

### Краткое описание системы

**Run Application** — мобильное приложение для трекинга пробежек с элементами геймификации (захват территорий на карте). Пользователь регистрируется, авторизуется, запускает трекинг пробежки; GPS-координаты записываются в реальном времени; по завершении пробежки backend вычисляет замкнутые контуры маршрута и формирует полигоны — «захваченные территории». Территории других пользователей, попавшие в зону захвата, уменьшаются. Результаты отображаются на карте в виде цветных полигонов.

**Стек технологий:** Flutter (клиент), FastAPI (backend REST API), PostgreSQL + PostGIS (база данных с пространственными расширениями), Yandex Cloud Functions (FaaS для фоновых задач).

| Элемент SADT | Описание |
|---|---|
| **Вход (Input)** | Данные пользователя (email, пароль, имя, цвет территории); GPS-координаты (широта, долгота, высота, точность, скорость) |

| Блок | Название | Вход | Выход |
|------|----------|------|-------|
| **A1.1** | Валидация входных данных | Email, пароль, имя пользователя | Валидированные данные (или ошибка 422) |

**Механизм:** Pydantic (валидация), passlib с Argon2 (хэширование), PyJWT (генерация/верификация токенов), PostgreSQL (таблицы `auth_identities`, `refresh_tokens`).

| Блок | Название | Вход | Выход |

| **A2.2** | Завершение пробежки | Точки + паузы → POST /runs/finish | Запись в БД (runs, run_points, run_pauses), LineString маршрута, результаты (дистанция, время) |

**Механизм:** Geolocator (поток GPS), connectivity_plus (мониторинг сети), FastAPI (REST API, endpoint `/runs/finish`), PostgreSQL + PostGIS (функции `compute_capture_polygons`, `finalize_run_capture`, операторы `ST_Polygonize`, `ST_Union`, `ST_Difference`, `ST_Snap`).

## Заключение

В ходе работы были построены SADT-диаграммы (нотация IDEF0) для основных бизнес-процессов мобильного приложения **Run Application**:

1. **Контекстная диаграмма (A-0)** — общий процесс использования приложения с указанием входов (данные пользователя, GPS-координаты), выходов (результаты пробежки, территории, уведомления), управления (правила геймификации, JWT-политика) и механизмов (Flutter, FastAPI, PostGIS).

2. **Декомпозиция A0** — разбиение на четыре основных подпроцесса: авторизация (A1), трекинг пробежки (A2), захват территории (A3), отображение результатов (A4).

3. **Декомпозиция A1 (авторизация)** — детализация процесса регистрации/входа: валидация данных → хэширование пароля → генерация JWT-токенов → обновление токенов (refresh).

4. **Декомпозиция A2+A3 (трекинг и захват)** — детализация основного игрового процесса: запись GPS-точек → завершение пробежки → вычисление полигонов захвата (замкнутые контуры) → обновление территорий через пространственные операции PostGIS.

Диаграммы отражают специфику приложения: использование пространственных данных (PostGIS), JWT-аутентификацию с ротацией токенов, геймификацию через захват территорий на основе GPS-треков.
