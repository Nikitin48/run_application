# Структура презентации: Проектирование и реализация Run Application

## Слайд 1: Обзор проекта
**Что показать:**
- Название проекта: "Run Application - Трекер пробежек с геймификацией"
- Архитектура системы (схема из 3 компонентов):
  ```
  [Flutter Frontend] ←→ [FastAPI Backend] ←→ [PostgreSQL + PostGIS]
  ```
- Основная идея: пользователи бегают, захватывают территории на карте, отнимают их у других
- Технологический стек:
  - Frontend: Flutter (Dart), Riverpod, GoRouter
  - Backend: Python FastAPI, Pydantic
  - Database: PostgreSQL 15+, PostGIS

**Визуализация:**
- Простая блок-схема архитектуры (3 блока с стрелками)
- Логотипы технологий (опционально)

## Слайд 2: Проектирование базы данных
**Что показать:**

### ER-диаграмма (основные сущности):
```
users (id, username, display_name)
  ├── auth_identities (email/phone, password_hash)
  ├── refresh_tokens
  ├── runs (track_line, distance, elapsed_s, paused_s)
  │     ├── run_points (lat, lng, ts, accuracy)
  │     └── run_pauses (started_at, ended_at, reason)
  ├── territories (geom: MultiPolygon) ← PostGIS
  ├── user_stats (run_count, total_distance, owned_area)
  └── user_last_notification (territory_stolen)
```

### Ключевые решения:
1. **PostGIS для геоданных**: 
   - `territories.geom` - MultiPolygon (SRID 4326)
   - `runs.track_line` - LineString (SRID 4326)
   - Индексы GIST для быстрых пространственных запросов

2. **Нормализация данных**:
   - Отдельные таблицы для точек пробежки (`run_points`)
   - Отдельная таблица для пауз (`run_pauses`)
   - Агрегированная статистика в `user_stats`

3. **Безопасность**:
   - Хеши паролей в `auth_identities`
   - Refresh token rotation с хешированием

**Визуализация:**
- ER-диаграмма (можно нарисовать в draw.io, dbdiagram.io, или просто схематично)
- Пример структуры таблицы `territories` с типом `geometry(MultiPolygon, 4326)`
- Скриншот индексов (GIST для геоданных)

## Слайд 3: Реализация БД - PostGIS функции
**Что показать:**

### Функция `compute_capture_polygons`:
- **Вход**: LineString (трек пробежки, SRID 4326), `tol_m` (10м), `min_area_m2` (150м²)
- **Процесс**:
  1. Преобразование в Web Mercator (3857) для работы в метрах
  2. Self-snapping (замыкание почти-замкнутых контуров в радиусе `tol_m`)
  3. Node (разбиение на пересечениях для обработки "восьмерок")
  4. Polygonize (создание полигонов из замкнутых контуров)
  5. Валидация и извлечение полигонов
  6. Фильтрация по минимальной площади (`min_area_m2`)
  7. Обратное преобразование в WGS84 (4326)
- **Выход**: MultiPolygon (захваченные территории, SRID 4326)

**📖 Подробное объяснение:** см. `docs/compute_capture_polygons_explained.md` и `docs/compute_capture_polygons_visual_scheme.txt`

### Функция `finalize_run_capture`:
- Вычисляет захваченные полигоны
- **Перераспределение территорий**:
  - Находит жертв (территории пересекаются с захватом)
  - Вычитает захваченную область из территорий жертв (`ST_Difference`)
  - Добавляет захват к территории бегуна (`ST_Union`)
- Обновляет статистику и уведомления

**Визуализация:**
- Псевдокод или упрощенная схема алгоритма
- Пример SQL запроса:
  ```sql
  SELECT capture_area_m2, victims_count 
  FROM finalize_run_capture(run_id, 10, 150);
  ```
- Диаграмма процесса: "Трек → Полигоны → Перераспределение → Статистика"

## Слайд 4: Backend API - FastAPI
**Что показать:**

### Архитектура API:
```
/auth
  ├── POST /register
  ├── POST /login
  └── POST /refresh

/runs
  └── POST /finish  (загрузка пробежки + автоматический захват)

/territories
  └── GET /?minLng&minLat&maxLng&maxLat  (GeoJSON)

/notifications
  └── GET /last  (последнее уведомление)

/me
  └── GET /  (профиль пользователя)
```

### Ключевые особенности:
1. **Pydantic модели** для валидации:
   - `RunFinishRequest` (points, pauses, timestamps)
   - Автоматическая валидация данных

2. **Обработка пробежки** (`POST /runs/finish`):
   - Вычисление расстояния (Haversine)
   - Создание LineString из точек
   - Сохранение в БД
   - Вызов `finalize_run_capture()` для захвата территорий

3. **Swagger документация**: `/docs`

**Визуализация:**
- Скриншот Swagger UI (`http://127.0.0.1:8000/docs`)
- Пример запроса/ответа:
  ```json
  POST /runs/finish
  {
    "started_at": "2025-12-15T10:00:00Z",
    "ended_at": "2025-12-15T10:10:00Z",
    "points": [...],
    "pauses": []
  }
  ```
- Диаграмма потока данных: "Flutter → FastAPI → PostgreSQL → PostGIS функция"

## Слайд 5: Frontend - Flutter приложение
**Что показать:**

### Архитектура:
- **State Management**: Riverpod (ProviderScope)
- **Routing**: GoRouter
- **HTTP Client**: Dio
- **Локализация**: flutter_localizations

### Основные экраны/функции:
1. **Карта территорий**: отображение MultiPolygon из GeoJSON
2. **Трекер пробежки**: 
   - Старт/Пауза/Завершение
   - Отслеживание GPS точек
   - Отображение на карте в реальном времени
3. **Профиль**: статистика (дистанция, количество пробежек, площадь территории)
4. **Уведомления**: о захвате территории

### Интеграция с бекендом:
- Авторизация (JWT tokens)
- Загрузка завершенной пробежки
- Получение территорий по bbox для карты

**Визуализация:**
- **Скриншоты приложения**:
  1. Карта с территориями (разные цвета для разных пользователей)
  2. Экран трекера пробежки (кнопки Start/Pause/Finish, счетчик точек)
  3. Профиль со статистикой
- Схема компонентов Flutter (widget tree упрощенно)
- Пример кода виджета (например, `RunControlsCard`)

## Советы по оформлению:
1. **Единый стиль**: используйте одну цветовую схему
2. **Минимум текста**: больше визуализаций, меньше списков
3. **Код**: показывайте только ключевые фрагменты, не весь файл
4. **Диаграммы**: используйте простые блок-схемы, не перегружайте деталями
5. **Скриншоты**: делайте их четкими, обрезайте лишнее
