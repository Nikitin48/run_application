# Постоянное хранение данных системы

## PostgreSQL + PostGIS

1. Таблица `users`
- `id` (PK) - уникальный идентификатор пользователя.
- `username` - уникальный логин пользователя.
- `display_name` - отображаемое имя в интерфейсе.
- `territory_color` - цвет территории пользователя (HEX).
- `is_banned` - признак блокировки аккаунта.
- `created_at` - дата и время создания пользователя.
- `updated_at` - дата и время последнего обновления профиля.

2. Таблица `auth_identities`
- `id` (PK) - уникальный идентификатор записи авторизации.
- `user_id` (FK -> `users.id`) - ссылка на владельца учетной записи.
- `provider` - тип провайдера авторизации (`email`/`phone`).
- `identifier` - значение идентификатора (email или телефон).
- `password_hash` - хэш пароля пользователя.
- `verified_at` - момент подтверждения идентификатора.
- `created_at` - дата и время создания записи.
- `updated_at` - дата и время последнего изменения записи.

3. Таблица `refresh_tokens`
- `id` (PK) - уникальный идентификатор refresh-токена.
- `user_id` (FK -> `users.id`) - пользователь, которому принадлежит токен.
- `token_hash` - хэш значения refresh-токена.
- `created_at` - дата и время выдачи токена.
- `expires_at` - дата и время истечения токена.
- `revoked_at` - дата и время отзыва токена (если отозван).
- `replaced_by_token_hash` - хэш нового токена при ротации.
- `user_agent` - клиентское устройство/браузер сессии.
- `ip` - IP-адрес, с которого получен токен.

4. Таблица `runs`
- `id` (PK) - уникальный идентификатор пробежки.
- `user_id` (FK -> `users.id`) - владелец пробежки.
- `status` - статус обработки пробежки (`draft`/`finished`/`processed`/`failed`).
- `started_at` - дата и время начала пробежки.
- `ended_at` - дата и время завершения пробежки.
- `distance_m` - пройденная дистанция в метрах.
- `elapsed_s` - общее время пробежки в секундах.
- `paused_s` - суммарное время на паузе в секундах.
- `moving_s` - время движения без пауз в секундах.
- `capture_area_m2` - площадь захваченной территории в квадратных метрах.
- `victims_count` - число пользователей, у которых отнята территория.
- `avg_pace_s_per_km` - средний темп (секунд на километр).
- `points` - исходные точки трека в формате JSON.
- `track_line` - нормализованная геометрия маршрута (`LineString`).
- `processing_error` - текст ошибки, если обработка завершилась неуспешно.
- `created_at` - дата и время создания записи пробежки.
- `updated_at` - дата и время последнего обновления записи.

5. Таблица `run_points`
- `run_id` (PK, FK -> `runs.id`) - ссылка на пробежку.
- `seq` (PK) - порядковый номер точки в пробежке.
- `ts` - временная метка точки.
- `lat` - широта точки.
- `lng` - долгота точки.
- `altitude_m` - высота в метрах (если доступна).
- `accuracy_m` - точность GPS в метрах.
- `speed_mps` - скорость в метрах в секунду (если доступна).

6. Таблица `run_pauses`
- `id` (PK) - уникальный идентификатор паузы.
- `run_id` (FK -> `runs.id`) - ссылка на пробежку.
- `started_at` - дата и время начала паузы.
- `ended_at` - дата и время окончания паузы.
- `reason` - причина паузы (`manual`/`gps_lost`/`internet_lost`).
- `created_at` - дата и время создания записи паузы.

7. Таблица `territories`
- `user_id` (PK, FK -> `users.id`) - пользователь-владелец территории.
- `geom` - геометрия территории (`MultiPolygon`).
- `updated_at` - дата и время последнего обновления территории.

8. Таблица `user_stats`
- `user_id` (PK, FK -> `users.id`) - пользователь, для которого рассчитана статистика.
- `run_count` - общее количество пробежек.
- `total_distance_m` - суммарная дистанция в метрах.
- `total_elapsed_s` - суммарное общее время в секундах.
- `total_paused_s` - суммарное время пауз в секундах.
- `total_moving_s` - суммарное время движения в секундах.
- `owned_area_m2` - текущая площадь территории пользователя.
- `updated_at` - дата и время последнего обновления статистики.

9. Таблица `user_last_notification`
- `user_id` (PK, FK -> `users.id`) - пользователь-получатель уведомления.
- `kind` - тип уведомления (например, `territory_stolen`).
- `attacker_user_id` (FK -> `users.id`) - пользователь-инициатор события.
- `run_id` (FK -> `runs.id`) - пробежка, связанная с уведомлением.
- `stolen_area_m2` - площадь потерянной территории в квадратных метрах.
- `payload` - дополнительные данные уведомления в JSON.
- `created_at` - дата и время формирования уведомления.

## Secure Storage (мобильный клиент)

1. Хранилище `auth_tokens`
- `access_token` - краткоживущий токен доступа к API.
- `refresh_token` - долгоживущий токен для обновления `access_token`.
