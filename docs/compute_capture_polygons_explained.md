# Подробное объяснение функции `compute_capture_polygons`

## 📋 Сигнатура функции

```sql
CREATE OR REPLACE FUNCTION compute_capture_polygons(
  p_track_line geometry,           -- Вход: LineString (трек пробежки)
  p_tol_m double precision DEFAULT 10,      -- Допуск замыкания в метрах
  p_min_area_m2 double precision DEFAULT 150  -- Минимальная площадь полигона в м²
)
RETURNS geometry  -- Выход: MultiPolygon (захваченные территории)
```

---

## 📥 Что принимает функция

### Параметры:

1. **`p_track_line`** (geometry, LineString, SRID 4326)
   - Трек пробежки в формате LineString
   - Координаты в WGS84 (широта/долгота)
   - Пример: `LINESTRING(37.62 55.75, 37.63 55.75, 37.63 55.76, 37.62 55.76, 37.62 55.75)`
   - Это замкнутый контур (петля)

2. **`p_tol_m`** (double precision, по умолчанию 10)
   - Допуск "почти замыкания" в метрах
   - Если начало и конец трека находятся на расстоянии ≤ 10м, они считаются замкнутыми
   - Используется для обработки неточных GPS данных

3. **`p_min_area_m2`** (double precision, по умолчанию 150)
   - Минимальная площадь полигона в квадратных метрах
   - Полигоны меньше этого размера отфильтровываются (чтобы не плодить мусор)

---

## 📤 Что возвращает функция

**MultiPolygon** (geometry, SRID 4326)
- Один или несколько полигонов, представляющих захваченные территории
- Если трек не образует замкнутых контуров → `MULTIPOLYGON EMPTY`
- Если все полигоны меньше `p_min_area_m2` → `MULTIPOLYGON EMPTY`

---

## 🔄 Алгоритм работы (пошагово)

### Шаг 0: Входные данные

```
Вход: LineString (трек пробежки)
Пример: пользователь пробежал по кругу

GPS точки:
A → B → C → D → E → F → A (почти замкнулся, но не точно)
```

**Визуализация:**
```
     F ──── E
    ╱         ╲
   ╱           ╲
  A             D
   ╲           ╱
    ╲         ╱
     B ──── C
     
(Начало A и конец F находятся на расстоянии ~8 метров)
```

---

### Шаг 1: Преобразование в Web Mercator (SRID 3857)

**Зачем:** 
- WGS84 (4326) работает в градусах, что неудобно для вычисления расстояний в метрах
- Web Mercator (3857) - проекция в метрах, идеальна для вычисления площадей и расстояний

```sql
line_m := ST_Transform(p_track_line, 3857);
```

**Что происходит:**
- Координаты преобразуются из градусов (lat/lng) в метры (x/y)
- Теперь можно точно измерять расстояния и площади

**Визуализация:**
```
До:  LINESTRING(37.62 55.75, 37.63 55.75, ...)  [градусы]
После: LINESTRING(4190000 7500000, 4191000 7500000, ...)  [метры]
```

---

### Шаг 2: Self-Snapping (замыкание почти-замкнутых контуров)

**Проблема:** GPS неточен, начало и конец трека могут не совпадать точно

**Решение:** Если точки находятся на расстоянии ≤ `p_tol_m`, "склеиваем" их

```sql
snapped := ST_Snap(line_m, line_m, p_tol_m);
```

**Что делает `ST_Snap`:**
- Берет каждую точку линии
- Ищет другие точки в радиусе `p_tol_m` (10 метров)
- Если находит - перемещает точку к ближайшей
- **Результат:** почти-замкнутые контуры становятся точно замкнутыми

**Визуализация:**

**До snapping:**
```
     F ──── E
    ╱         ╲
   ╱           ╲
  A             D
   ╲           ╱
    ╲         ╱
     B ──── C
     
A и F на расстоянии 8м (меньше tol_m=10м)
```

**После snapping:**
```
     F ──── E
    ╱         ╲
   ╱           ╲
  A ─────────── D  (A и F "склеены")
   ╲           ╲
    ╲           ╲
     B ──── C
     
Теперь контур точно замкнут!
```

---

### Шаг 3: Node (разбиение на пересечениях)

**Зачем:** Если трек пересекается сам с собой (например, "восьмерка"), нужно разбить на отдельные сегменты

```sql
noded := ST_Node(snapped);
```

**Что делает `ST_Node`:**
- Находит все точки пересечения линии с самой собой
- Разбивает линию на отдельные сегменты в этих точках
- Каждый сегмент теперь независим

**Визуализация:**

**Пример "восьмерки":**
```
До Node:
    A ──── B
    │     │
    │  X  │  (пересечение в точке X)
    │     │
    D ──── C
```

**После Node:**
```
    A ──── B
    │     │
    │  X  │  (X теперь узел, линия разбита)
    │     │
    D ──── C
    
Сегменты: A→B→X, X→C→D→X, X→A
```

---

### Шаг 4: Polygonize (создание полигонов)

**Зачем:** Превратить замкнутые контуры в полигоны

```sql
poly_coll := ST_Polygonize(noded);
```

**Что делает `ST_Polygonize`:**
- Анализирует разбитую линию
- Находит все замкнутые контуры (faces)
- Создает из них полигоны
- **Результат:** GeometryCollection с полигонами

**Визуализация:**

**Вход (noded):**
```
    A ──── B
    │     │
    │  X  │
    │     │
    D ──── C
```

**Выход (poly_coll):**
```
GeometryCollection {
  Polygon(A→B→X→A),      // Верхний треугольник
  Polygon(X→C→D→X),      // Нижний треугольник
  Polygon(A→B→C→D→A)     // Внешний прямоугольник
}
```

**Важно:** Для "восьмерки" получится **несколько полигонов**, а не один!

---

### Шаг 5: Извлечение и валидация полигонов

```sql
poly_m := ST_CollectionExtract(ST_MakeValid(ST_UnaryUnion(poly_coll)), 3);
```

**Разбор по частям:**

1. **`ST_UnaryUnion(poly_coll)`**
   - Объединяет перекрывающиеся полигоны
   - Убирает дубликаты

2. **`ST_MakeValid(...)`**
   - Исправляет геометрические ошибки
   - Убирает самопересечения, делает полигоны валидными

3. **`ST_CollectionExtract(..., 3)`**
   - Извлекает только полигоны (тип 3)
   - Отбрасывает точки и линии

**Результат:** MultiPolygon с валидными полигонами

---

### Шаг 6: Фильтрация по минимальной площади

**Зачем:** Убрать "мусорные" маленькие полигоны (артефакты GPS неточностей)

```sql
filtered_m := (
  SELECT COALESCE(
    ST_Multi(ST_Union(geom)),
    ST_SetSRID('MULTIPOLYGON EMPTY'::geometry, 3857)
  )
  FROM (
    SELECT (ST_Dump(poly_m)).geom AS geom
  ) d
  WHERE ST_Area(d.geom) >= p_min_area_m2
);
```

**Что происходит:**

1. **`ST_Dump(poly_m)`** - разбивает MultiPolygon на отдельные полигоны
2. **`ST_Area(d.geom)`** - вычисляет площадь каждого полигона (в м², т.к. мы в SRID 3857)
3. **`WHERE ST_Area(...) >= 150`** - оставляет только полигоны ≥ 150 м²
4. **`ST_Union(...)`** - объединяет оставшиеся полигоны обратно в MultiPolygon

**Визуализация:**

**До фильтрации:**
```
MultiPolygon {
  Polygon A (500 м²)  ← оставляем
  Polygon B (50 м²)   ← удаляем (< 150 м²)
  Polygon C (200 м²)  ← оставляем
  Polygon D (30 м²)   ← удаляем (< 150 м²)
}
```

**После фильтрации:**
```
MultiPolygon {
  Polygon A (500 м²)
  Polygon C (200 м²)
}
```

---

### Шаг 7: Обратное преобразование в WGS84

```sql
filtered_4326 := ST_Transform(filtered_m, 4326);
RETURN ST_Multi(ST_CollectionExtract(ST_MakeValid(filtered_4326), 3));
```

**Зачем:** Вернуть результат в исходную систему координат (WGS84)

**Что происходит:**
- Преобразуем из метров (3857) обратно в градусы (4326)
- Финальная валидация
- Возвращаем MultiPolygon

## 📝 Примеры использования

### Пример 1: Простая петля

**Вход:**
```sql
SELECT compute_capture_polygons(
  ST_SetSRID(
    ST_GeomFromText('LINESTRING(37.62 55.75, 37.63 55.75, 37.63 55.76, 37.62 55.76, 37.62 55.75)'),
    4326
  ),
  10,   -- tol_m
  150   -- min_area_m2

```

**Выход:**
```
MULTIPOLYGON(((37.62 55.75, 37.63 55.75, 37.63 55.76, 37.62 55.76, 37.62 55.75)))
```

**Визуализация:**
```
┌─────────┐
│         │  ← Захваченная территория
│         │
└─────────┘
```

### Пример 2: "Восьмерка" (два пересекающихся контура)

**Вход:**

## 🔗 Где используется функция

Функция вызывается внутри `finalize_run_capture()`:

```sql
-- В функции finalize_run_capture:
v_capture := compute_capture_polygons(v_line, p_tol_m, p_min_area_m2);
```

**Полный процесс:**
1. Пользователь завершает пробежку → `POST /runs/finish`
2. Backend сохраняет трек в БД
3. Вызывается `finalize_run_capture(run_id)`
4. Внутри вызывается `compute_capture_polygons()` → получаем MultiPolygon
5. Этот MultiPolygon используется для перераспределения территорий

---

## ⚙️ Параметры и их влияние

### `p_tol_m` (допуск замыкания)

- **Маленькое значение (5м):** Строже, требует точного замыкания
  - ✅ Меньше ложных срабатываний
  - ❌ Может пропустить почти-замкнутые контуры

- **Большое значение (20м):** Мягче, замыкает даже неточные контуры
  - ✅ Ловит больше контуров
  - ❌ Может "замкнуть" контуры, которые не должны быть замкнуты

**Рекомендация:** 10 метров - хороший баланс для GPS данных

---

### `p_min_area_m2` (минимальная площадь)

- **Маленькое значение (50м²):** Больше маленьких полигонов
  - ✅ Захватывает маленькие территории
  - ❌ Много "мусорных" полигонов от GPS неточностей

- **Большое значение (500м²):** Только большие территории
  - ✅ Только значимые захваты
  - ❌ Пропускает маленькие, но валидные территории

**Рекомендация:** 150-300 м² - разумный компромисс

## 🎨 Визуальная схема: от GPS точек до полигонов

```
GPS точки с устройства:
  A(37.62, 55.75)
  B(37.63, 55.75)
  C(37.63, 55.76)
  D(37.62, 55.76)
  E(37.6201, 55.7501)  ← почти вернулся к A
         │
         ▼
LineString в БД:
  LINESTRING(37.62 55.75, 37.63 55.75, 37.63 55.76, 37.62 55.76, 37.6201 55.7501)
         │
         ▼
[compute_capture_polygons вызывается]
         │
         ├─→ Transform to 3857 (метры)
         ├─→ Snap (замыкание)
         ├─→ Node (разбиение)
         ├─→ Polygonize (создание полигонов)
         ├─→ Filter (по площади)
         └─→ Transform to 4326 (градусы)
         │
         ▼
MultiPolygon:
  MULTIPOLYGON(((37.62 55.75, 37.63 55.75, 37.63 55.76, 37.62 55.76, 37.62 55.75)))
         │
         ▼
Используется в finalize_run_capture:
  - Находит жертв (ST_Intersects)
  - Убирает у жертв (ST_Difference)
  - Добавляет бегуну (ST_Union)
```

## 💡 Ключевые моменты

1. **Работа в метрах:** Преобразование в Web Mercator необходимо для точных вычислений площадей
2. **Self-snapping:** Критически важно для обработки неточных GPS данных
3. **Поддержка "восьмерок":** Функция корректно обрабатывает сложные контуры
4. **Фильтрация:** Убирает артефакты GPS (маленькие полигоны)
5. **Валидация:** Все полигоны проходят проверку на валидность

## 🔍 Отладка функции

Если функция возвращает `MULTIPOLYGON EMPTY`, проверьте:

1. **Трек замкнут?**
   ```sql
   SELECT ST_IsClosed(track_line) FROM runs WHERE id = '...';
   ```

2. **Расстояние между началом и концом?**
   ```sql
   SELECT ST_Distance(
     ST_StartPoint(track_line),
     ST_EndPoint(track_line)
   ) * 111000 as distance_m  -- примерное преобразование в метры
   FROM runs WHERE id = '...';
   ```

3. **Площадь полигонов достаточна?**
   - Уменьшите `p_min_area_m2` для теста

4. **Трек не пустой?**
   ```sql
   SELECT ST_IsEmpty(track_line) FROM runs WHERE id = '...';
   ```
