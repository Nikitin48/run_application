# Справка: что ещё можно добавить в бекенд (и когда это реально нужно)

Ниже — **необязательные**, но часто “неизбежные” вещи для трекера с геймификацией и захватом территорий.
Пока можно не делать — это список “что поставить в бэклог”, чтобы не забыть.

## 1) Античит и валидация пробежек (рекомендуется рано)

**Зачем**: у вас соревнование и “отжим” территорий → накрутки быстро убьют баланс.

**Минимум**:
- флаги в `runs`: `is_suspicious boolean`, `suspicious_reason text`
- правила:
  - отбрасывать точки с плохой `accuracy`
  - игнорировать “телепорты” (слишком большой скачок за короткое время)
  - лимитировать “нереальную скорость”

**Когда внедрять**: как только появятся первые пользователи и рейтинг/территории станут важными.

## 2) Очередь задач / надёжная обработка (по мере усложнения)

**Зачем**: обработка захвата и перекраски может быть тяжёлой; нужны ретраи и контроль ошибок.

**Варианты**:
- таблица `jobs` в БД (просто и локально)
- внешняя очередь (позже): Redis + worker

**Когда внедрять**: когда `finalize` становится долгим/падает/требуются повторы.

## 3) Лидерборды (когда появится соревнование)

**Зачем**: рейтинг по площади/дистанции/сериям тренировок.

**Как**:
- кэш/материализованные представления:
  - по периодам: день/неделя/месяц
  - по scope: глобально / город / bbox

**Когда внедрять**: после стабилизации базовой механики захвата.

## 4) Команды (когда точно решите добавлять)

**Зачем**: командный соревновательный режим.

**Минимум таблиц**:
- `teams`, `team_members`, `team_stats`

## 5) Модерация и безопасность

**Зачем**: бан/разбан, блокировка накрутчиков, разбор спорных ситуаций.

**Минимум**:
- `users.is_banned` (уже есть)
- журнал: `admin_actions` (кто/что/когда/почему)

## 6) Оптимизация выдачи территорий на карту

**Зачем**: чтобы карта не лагала и не тянула мегабайты геометрии.

**Минимум**:
- API выдаёт территории по `bbox`
- упрощение геометрии по zoom: `ST_SimplifyPreserveTopology`

## 7) Приватность (если понадобится)

**Зачем**: скрывать дом/работу.

**Минимум**:
- настройки пользователя: `hide_start_finish_m`
- при показе/хранении трека — “обрезать” первые/последние N метров

## 8) Уведомления (у вас сейчас “только последнее”)

**Если захотите историю**:
- отдельная таблица событий (например `notifications`)
- поля `read_at` / `seen`
