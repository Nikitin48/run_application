# План: очистка токенов через Yandex Cloud Functions

Цель: по расписанию удалять из таблицы `refresh_tokens` устаревшие и отозванные записи, не нагружая основной FastAPI backend.

---

## 1. Что делаем

- **Действие:** `DELETE` из `refresh_tokens` строк, где:
  - `expires_at < now()` (токен истёк), **или**
  - `revoked_at IS NOT NULL` (токен уже отозван при refresh).
- **Триггер:** вызов функции по расписанию (cron), например раз в сутки ночью.
- **Среда:** Yandex Cloud Functions (Python 3.x), доступ к той же БД, что и backend (Yandex Managed PostgreSQL).

### Этап 3. Логика очистки и безопасность

| Шаг | Действие | Результат |
|-----|----------|------------|
| 3.1 | Выполнять только `DELETE FROM refresh_tokens WHERE expires_at < now() OR revoked_at IS NOT NULL` | Удаляются только неактуальные записи |
| 3.2 | Опционально: лимитировать число удаляемых строк за один запуск (например, 10_000) и логировать количество | Защита от случайного массового удаления и удобный мониторинг |
| 3.3 | Логировать результат (удалено N строк) и ошибки в stdout/stderr | Просмотр логов в консоли Yandex Cloud |

**Критерий готовности:** один прогон не трогает актуальные токены и удаляет только истёкшие/отозванные.

## 3. Структура кода функции (рекомендуемая)

```
faas/
  token_cleanup/
    handler.py      # точка входа: handler(event, context)
    requirements.txt
```

**handler.py (псевдокод):**

- Читать из env: `DATABASE_URL` или `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SSLMODE`.
- Собрать URL при отсутствии `DATABASE_URL`.
- Подключиться к PostgreSQL, выполнить:
  - `DELETE FROM refresh_tokens WHERE expires_at < now() OR revoked_at IS NOT NULL` (опционально с `LIMIT N`).
- Залогировать количество удалённых строк, закрыть соединение.
- Вернуть из handler структуру для логов (например `{"deleted": N}`).

Формат входа в Yandex Cloud Functions: первый аргумент — `event` (для timer обычно пустой/служебный), второй — `context`. Для очистки токенов содержимое `event` можно не использовать.

## 4. Риски и митигации

| Риск | Митигация |
|------|-----------|
| Пароль БД в открытом виде в настройках функции | Использовать секреты Yandex Lockbox или переменные окружения с ограничением прав доступа к ресурсу функции |
| Сеть: функция не достучится до БД | Убедиться, что БД имеет публичный доступ или функция в той же VPC; при необходимости настроить security groups / white list |
| Слишком частый или тяжёлый запуск | Cron раз в сутки; при росте объёма — батчи (LIMIT + несколько вызовов подряд или следующее срабатывание) |
