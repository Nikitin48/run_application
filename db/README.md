# DB (PostgreSQL + PostGIS) — финальная схема под механику “петли + перекраска”

## Что здесь

- `schema.sql` — таблицы, индексы, ограничения
- `functions.sql` — PostGIS-функции:
  - построение MultiPolygon захвата из трека (петли, включая “восьмёрки”)
  - finalize: перекраска территорий + запись **последнего** уведомления жертвам + обновление user_stats

## Как применить (pgAdmin)

1) В вашей БД включите расширения:

```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
```

2) Выполните по очереди:
- `schema.sql`
- `functions.sql`

## Параметры, которые вы будете крутить

- **`tol_m`**: допуск “почти замыкания” в метрах (5–10м, на MVP чаще ставят 10)
- **`min_area_m2`**: минимальная площадь полигона захвата (чтобы не плодить мусор), например 150–300 м²

## Время и паузы (статистика бега)

Для каждой пробежки (`runs`) рекомендуем хранить:
- **`elapsed_s`**: общее время (ended_at - started_at), включая паузы
- **`paused_s`**: сумма пауз (ручных и авто)
- **`moving_s`**: `elapsed_s - paused_s`

Паузы лучше хранить интервалами:
- `run_pauses(reason in manual|gps_lost|internet_lost)`

Сырые точки (`run_points`) нужны, чтобы честно считать moving-time и дистанцию (и делать античит).
